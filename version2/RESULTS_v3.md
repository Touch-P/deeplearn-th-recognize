# version 3 — fine-tune ด้วย manual class-weighted loss

สร้างอัตโนมัติจากไฟล์ผลลัพธ์จริงด้วย `make_note_v3.py` เมื่อ 2026-09-24

## ทำอะไร

- โหลด checkpoint ของ version 2 (`best_model.pth`) มา fine-tune ต่อ **5 epochs** ไม่ได้เทรนใหม่จากศูนย์
- ใส่ `weight` ต่อคลาสใน `nn.CrossEntropyLoss` เจาะจง **21 คลาส** ที่ confusion matrix ของ v2 ชี้ว่ายังสับสนกันเป็นระบบ (คง `label_smoothing=0.1` เดิมไว้ด้วย)
- learning rate = `1e-05` = 1/10 ของตอนเทรนหลัก (`0.0001`) ลดแบบ CosineAnnealingLR ตลอด 5 epochs
- dataloader และ augmentation ใช้ pipeline เดิมของ v2 ทั้งหมด (manifest ที่ balance ทุกคลาส เป็น 3,819 ภาพ = 274,968 ภาพต่อ epoch) ไม่เปลี่ยนอะไร
- optimizer เริ่มใหม่ ไม่โหลด state ของ v2 เพราะ state นั้นผูกกับตาราง lr ของรอบก่อน ที่ลดลงไปจนเกือบศูนย์แล้ว

## ที่มาของน้ำหนัก (อิง confusion matrix จุดไหน)

นับ error ของแต่ละคลาสจาก `outputs/reports/05_confusion_matrix_val.csv` ของ v2 โดย

## ข้อควรระวังในการตีความ

1. **ชุด train ของ v2 balance อยู่แล้ว** (ทุกคลาส 3,819 ภาพเท่ากัน) การใส่ class weight จึงไม่ใช่การแก้ความไม่สมดุลของข้อมูล แต่เป็นการ *เพิ่มน้ำหนักความสำคัญ* ให้คลาสที่ยัง สับสน ซึ่งเป็นการถ่วงรอบที่สองทับของเดิม
2. **เพดานของสิ่งที่ทำได้มีน้อย** v2 เหลือ error แค่ 168 ครั้งจาก 11,913 ภาพ (1.4%) การเปลี่ยนแปลงระดับ 0.00X จึงอยู่ในช่วงที่ noise ของการเทรนอธิบายได้ ไม่ควรสรุปว่า เทคนิคนี้ดีหรือไม่ดีจากตัวเลขเดียว
3. **คู่ที่สับสนหนักสุดสับสนกันเอง** เช่น า ↔ ๅ ↔ ว ทั้งสามตัวได้ weight 3.0 เท่ากัน การถ่วงน้ำหนักทั้งกลุ่มพร้อมกันจึงไม่ได้บอกโมเดลว่าควรเอนไปทางไหน แค่บอกว่า "กลุ่มนี้สำคัญ" การแยกคู่พวกนี้ให้ดีขึ้นจริงน่าจะต้องใช้ความละเอียดภาพที่สูงกว่า 224×224 หรือ loss ที่ลงโทษเฉพาะคู่ (เช่น pairwise/metric learning) มากกว่าการถ่วงน้ำหนักคลาส
4. `val loss` ใช้ loss แบบไม่ถ่วงน้ำหนักเสมอ เพื่อให้เทียบกับ v2 ได้ตรง
